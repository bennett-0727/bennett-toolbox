# Design

## Context

现有组件约 300 条中文文案，直接逐条改成 `t("key")` 工作量大且容易漏。采用“中文原文即键”的运行时 JSX 包装层，统一拦截 JSX 子节点与文本属性，词典提供英文，动态消息用正则规则。

## Goals / Non-Goals

**Goals:**

- 中英即时切换、持久化、覆盖全部用户可见文案。
- 主进程对话框/悬浮窗与 IPC 错误同步语言。
- 1000×700 起无横向溢出，英文侧栏不截断。
- 用可重复的英文扫描 e2e 防止回退。

**Non-Goals:**

- 不增加第三种语言。
- 不翻译用户数据、文件名、Markdown 输出。
- 不改变模块业务逻辑与 IPC 协议（仅新增 set-language 事件）。

## Decisions

1. **运行时 JSX 翻译层**
   - Vite 插件把 `react/jsx-runtime` / `jsx-dev-runtime` 解析到本地包装，翻译字符串子节点、`title/placeholder/alt/aria-label`。
   - 词典以中文原文为键，动态消息用正则替换；中文模式原样返回。
   - 备选逐条 `t()` 改调用被否决：300+ 文案漏改风险高。

2. **语言状态由 App 管理**
   - `localStorage("bennett-language")` 初始化；切换时同步设置全局语言、`html.lang`、标题和 `set-language` IPC。
   - `<main key={language}>` 在切换时重挂载模块，避免残留旧语言状态。

3. **主进程本地化**
   - 主进程保存当前语言，原生对话框、悬浮窗 HTML 和 IPC 错误使用 `translate`。
   - 渲染进程仍会翻译主进程文本，形成双保险。

4. **响应式断点**
   - 复用已有 1180/1100/900 断点，补充英语侧栏 230px、nav 省略、语言胶囊按钮和 1000px 下的主区域 padding。
   - 语言图标使用内联 SVG。

## Risks / Trade-offs

- 运行时翻译按字符串匹配，用户数据若与 UI 文案完全相同可能被翻译 → 仅精确匹配词典，概率极低；后续可改为显式 key。
- 动态消息依赖正则规则，新增文案需补规则 → e2e 英文扫描 + 源字符串审计脚本兜底。
