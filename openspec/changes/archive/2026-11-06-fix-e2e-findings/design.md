# Design

## Context

见 `proposal.md`。两个问题都位于渲染进程模块内部，主进程 IPC 协议不需要调整。

## Goals / Non-Goals

**Goals:**

- 文档选择文件与拖拽使用同一套扩展名校验。
- 文件搜索根目录错误可见，子目录错误继续容错。
- e2e 覆盖修复后的行为与恢复路径。

**Non-Goals:**

- 不改变支持的文件类型列表。
- 不改变 MarkItDown 调用方式与错误清洗逻辑。
- 不增加主进程文件类型校验。

## Decisions

1. **文档模块复用现有 `w(path, name, size)` 校验函数**
   - `g()` 原实现直接 `t(N)` 设置文件，跳过 `CP` 校验；改为调用 `w(N.path, N.name, N.size)`，与拖拽路径一致。
   - 备选在主进程重复校验被否决：渲染进程已有唯一支持列表，重复维护易漂移。

2. **文件搜索按递归深度决定是否抛出目录错误**
   - `readdirSync` 的 catch 在 `depth === 0` 时重新抛出，外层 catch 统一设置 `error`；更深层继续忽略。
   - 外层错误文案加“搜索失败：”前缀，保留原始错误信息。
   - 备选“任何子目录错误都中断”被否决：一个无权限子目录不应让整次搜索失败。

## Risks / Trade-offs

- 根目录错误时结果列表为空且显示错误，用户需修正目录后重新输入关键词 → 文档与 e2e 明确该恢复路径。
- 子目录错误仍不可见，属于可接受的容错行为。
